# ТЗ №3 для агента репозитория BMGBRAND — ИИ должен отвечать сам, без заглушек

> Документ подготовлен агентом приложения **AdminBMG** для агента, работающего с репозиторием
> сайта `https://github.com/misha4323223/BMGBRAND`. Все изменения — ТОЛЬКО на сервере сайта.
> **Приоритет: ВЫСОКИЙ.** Сейчас агент на живых вопросах отвечает «Не удалось распознать команду».

## Контекст: что происходит в проде

Администратор в чате BOOOM AI спрашивает:
- «на какую сумму продался мерч людмил огурченко?»
- «сумма продаж мерча людмил огурченко»

…и получает «Не удалось распознать команду.» вместо ответа.

Эта фраза — фолбэк из `server/admin-agent.ts` (строки ~133 и ~150), который срабатывает,
когда Groq вернул ПУСТОЙ или нечитаемый ответ. То есть модель вызывается, но её ответ теряется.
Приложение AdminBMG уже страхует администратора локальным расчётом в этом случае,
но нужен фикс на корню.

## Причина (анализ кода)

В `processAdminCommand` (`server/admin-agent.ts`):
- модель `openai/gpt-oss-20b` — reasoning-модель: на аналитический вопрос она тратит много
  токенов на внутренние рассуждения; при `maxTokens: 2000` рассуждения съедают весь лимит,
  `delta.content` приходит пустым → `raw = ""` → заглушка;
- при ошибке JSON.parse нет повторной попытки — сразу заглушка;
- если модель вернула JSON с неизвестным `type` или пустым `text` — тоже заглушка.

## Задача 1: поднять лимит и снизить «рассуждение»

**Файл:** `server/admin-agent.ts`, вызов `groqCompleteStream`.

```ts
raw = await groqCompleteStream({
  baseUrl: groqBase,
  apiKey,
  model: "openai/gpt-oss-20b",
  messages,
  temperature: 0.1,
  maxTokens: 4000,          // было 2000
  reasoningEffort: "low",   // НОВОЕ — см. задачу 2
  signal: ctrl.signal,
});
```

## Задача 2: прокинуть `reasoning_effort` в groq-utils

**Файл:** `server/groq-utils.ts`, функция/тип `groqCompleteStream`.

Добавить в опции `reasoningEffort?: "low" | "medium" | "high"` и передавать его в тело
запроса Groq (`body.reasoning_effort`). Для gpt-oss это официальный параметр API:
он резко сокращает токены рассуждений и гарантирует непустой `content`.
Если параметр уже поддерживается — просто использовать `"low"` из задачи 1.

## Задача 3: один ретрай без JSON при пустом/битом ответе

**Файл:** `server/admin-agent.ts`, `processAdminCommand`.

После первого вызова, если `raw` пустой или `JSON.parse` упал — сделать ВТОРОЙ вызов
с дополнительной инструкцией, требующей обычного текста:

```ts
function isBadRaw(s: string): boolean {
  return !s || !s.trim();
}

// после первой попытки:
let parsed: any = null;
try { parsed = JSON.parse(raw); } catch { /* ниже ретрай */ }

if (!parsed) {
  if (isBadRaw(raw)) {
    // пусто — почти наверняка всё съели рассуждения; просим прямой текст
    const retryMessages = [
      ...messages,
      { role: "user" as const, content:
        "Предыдущий ответ был пустым. Ответь на последний вопрос администратора " +
        "обычным текстом по-русски, БЕЗ JSON. Если нужны данные — скажи, каких именно." },
    ];
    raw = await groqCompleteStream({ ...тот же конфиг..., messages: retryMessages });
    raw = String(raw || "").trim();
    try { parsed = JSON.parse(raw); } catch { parsed = null; }
  }
  if (!parsed) {
    // ретрай тоже не дал JSON — если есть текст, вернуть его как answer
    return { type: "answer", text: raw && raw.trim() ? raw.trim() :
      "Не получилось обработать запрос через ИИ. Попробуй переформулировать вопрос." };
  }
}
```

## Задача 4: убрать голую заглушку

**Файл:** `server/admin-agent.ts`.

Заменить оба `text: ... || "Не удалось распознать команду."` на понятные ответы:
- для пустого `parsed.text`: `"ИИ не смог сформировать ответ. Переформулируй вопрос — например: «сколько продалось <товар>», «выручка за месяц», «покажи брошенные корзины»."`
- для неизвестного `parsed.type`: логировать тип в консоль и возвращать такой же понятный текст.

Фраза «Не удалось распознать команду» больше нигде не должна возвращаться
(приложение ищет её как признак сбоя).

## Шаги проверки (после деплоя)

Из приложения AdminBMG (чат BOOOM AI):

1. «на какую сумму продался мерч людмил огурченко» → конкретная сумма + топ позиций (через analyze_orders).
2. «сумма продаж мерча людмил огурченко за месяц» → сумма с учётом периода.
3. «какая выручка за неделю по дням» → таблица.
4. Спросить что-то совсем бессвязное («asdfgh») → должен прийти Внятный текст-уточнение,
   НЕ «Не удалось распознать команду».
5. Регресс: «создай промокод TEST20 на 20%» → write-подтверждение работает.
